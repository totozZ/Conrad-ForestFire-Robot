## 两型号分别实现

| 行为 | H6215 profile | H3510 profile |
| --- | --- | --- |
| 速度帧 | 标准帧，`0x200 + CAN_ID`，4 字节小端 float | 同格式，独立型号入口 |
| 速度单位 | 协议 rad/s，接口 rps，乘/除 2π 转换 | 协议 rad/s，接口 rps，乘/除 2π 转换 |
| 使能/失能 ID | 按 V2 §7.2.1 示例取基础 CAN_ID | 按说明书取当前模式的控制 ID，即速度模式下 `0x200 + CAN_ID` |
| 使能/失能数据 | 7 个 FF，末字节 FC / FD | 7 个 FF，末字节 FC / FD |
| 反馈 | 已配置 Master ID，8 字节；低四位设备 ID、高四位状态，12 位速度映射 | 同类布局，按自身 V_MAX 解码 |

**特殊命令 ID 是到货核对重点。** H6215 V2 的代码示例使用基础 ID，H3510 的文字将启停归入对应模式控制帧。V2 教程还存在示例型号混用等编辑问题，不能据此断言所有实物固件完全一致。
实现没有“无反馈时自动尝试另一种 ID”的逻辑。先捕获官方软件针对实物的零目标使能与停止报文，再核对当前 profile；如版本不符，依据该实物资料修订 profile 和测试，不同时向多个候选 ID 盲发动作帧。

状态码只识别 0（停用）、1（使能）和 8–14（故障）；未知状态、错误 ID、错误 DLC、扩展帧、远程帧不会刷新反馈时间。
温度按原始温度字节读取。速度映射从 −V_MAX 到 +V_MAX，V_MAX 必须与实物读回一致；没有读取成功就不开放真机使能。
不发送电机标定、固件更新、寄存器写入、清错或保存零点命令。

## 测试证据分级

- **有原厂数值例子：** H6215 V2 中的 5 rad/s，转换为网页值 `5/(2π)` rps 后，应编码为 `00 00 A0 40`；帧 ID 用测试配置 CAN_ID=1 时为 0x201。
- **按原厂格式推导的结构测试：** H3510 采用相同 5 rad/s 数值检查浮点字节序；这是推导测试，不是 H3510 实物抓包或厂家数值用例。
- **合成反馈测试：** 检查 12 位端点、方向反转、状态码、温度、错误帧与时间戳。这些证明编解码符合所采用结构，不证明实际电机固件和参数匹配。
- **尚未完成：** 三台实物的原始报文对照、使能反馈、速度比例、模式、ID、内部超时保护、供电与机构停转。

TWAI 实现采用 [ESP-IDF v5.5.1 官方接口](https://docs.espressif.com/projects/esp-idf/en/v5.5.1/esp32s3/api-reference/peripherals/twai.html)，WebSocket 使用 [同版本 HTTP Server](https://docs.espressif.com/projects/esp-idf/en/v5.5.1/esp32s3/api-reference/protocols/esp_http_server.html)。软件构建版本已固定，不跟随 latest 自动升级。
