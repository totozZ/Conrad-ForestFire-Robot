## 到货后：逐步开放真实控制

| 阶段 | 操作 | 通过条件 / 记录 |
| --- | --- | --- |
| 0. 接线核对 | 断电核对板卡、8 pin 转接、极性、H/L、供电、终端、主控逻辑供电、实体停机 | 完成接口表，有实物依据；不依赖线色猜测 |
| 1. 官方工具单机 | 每台读取原始参数，不同时发 ESP32 动作指令 | 明确模式、ID、Master ID、映射范围和经典 CAN 速率；备份配置 |
| 2. ESP32 反馈 | 填板级配置，烧录真机；配置一台电机并标为已核对，其他保持未核对 | 不请求使能也能通过停用探测得到反馈，ID、失能状态、时间戳合理 |
| 3. 单个行走轮 | 轮子离地，先 0 目标使能，再按本轮已核对低速测试 | 方向正确，设定与反馈单位一致，松开后减速归零，单机停止后反馈失能 |
| 4. 第二个行走轮 | 独立完成阶段 2–3，再共总线 | 不串台、不碰 ID，不因左右安装方向误判转向 |
| 5. 控制失效测试 | 在受控低速条件下测试网页失焦、关闭、断 Wi-Fi；观察停机并导出日志 | 超时锁定，目标清零，重连必须重新取得控制权与使能，不自动续转 |
| 6. CAN 丢失与实体停机 | 先确认电机自身超时保护，再以适当的受控方式中断通信；另测实体动力切断 | 测量实际停转延时；即使 ESP32 停止报文不可达，仍能停机。记录停止滑行情况 |
| 7. H3510 无切削风险验证 | 两行走电机停用，先核对专用线束和供电，再单机读反馈、使能与低速启停 | 独立解锁生效，方向正确，启停与反馈符合预期；验证特殊命令 ID |
| 8. 机构空载 | 固定、防护、传动与停机条件满足后运行 | 没有异常擦碰、振动、松动，停止可靠；记录转速、供电和视频 |
| 9. 少量树叶 | 使用可记录的少量同条件叶片，观察进料与出料 | 有处理前后对照，记录推叶、缠绕、卡料、减速、人工干预和结论 |

任一步失败停在该步。不得用调高上限掩盖方向、单位或映射错误；也不因网页显示“命令已接受”就进入下一步。
真机 CAN 故障锁定后，先排除原因，再重启控制器。电机内部故障通过官方工具处理，不自动清错和重启。
H3510 尚未接入时保持其配置未核对，可以继续验证两台行走电机。
